# 项目优化日志 · 关闭屏幕（ScreenOff）

> **项目**：关闭屏幕 / ScreenOff —— 只关显示器、不影响任何程序运行的 Windows 小工具
> **记录日期**：2026-09-12
> **记录范围**：从需求萌芽到 v1.0.0 发布的全过程，含同类项目研究结论与每一次改动的动机推演
> **阅读方式**：第二章是「向外看」（同类标杆研究），第三章是「向内看」（本项目逐项改动），第四章是本次 README 重构的结构对照

## 一、背景：一个问题牵出另一个问题

事情的起点并不是「关屏」，而是**远程开机**。

用户在配置网易 UU 远程的「远程开机」功能时，客户端提示「未检测到有线网卡」。围绕这个报错做了一轮硬件与驱动排查，结论是：

| 排查项 | 实测结论 |
|---|---|
| 虚拟网卡／驱动能否实现唤醒 | **不能**。网卡唤醒依赖关机后仍带待机供电的**物理网卡**，虚拟网卡随系统关闭而消失，收不到魔术包 |
| 本机有线网卡 | 存在（板载 Realtek PCIe GbE），但 `Status=Disconnected` —— **网线未插** |
| 网卡驱动级唤醒设置 | 已全部开启（魔术封包唤醒、关机网络唤醒） |
| 无线网卡（RTL8852AE） | 在线，且已启用魔术包唤醒，但 WiFi 唤醒**仅对睡眠（S3）有效**，彻底关机无效 |

排查过程中顺带查到一条容易被忽略的电源设置：**本机在「接通电源」状态下，显示器被设为「从不关闭」**（仅电池模式 10 分钟）。也就是说，插着电使用时屏幕永远不会自己黑。

用户随即提出真正的痛点需求：

> 「查查本机关闭电脑屏幕的快捷键，如果没有，看看能不能写一个程序，点击直接关闭电脑屏幕，仅关闭屏幕，不影响运行，开启的按键是笔记本的电源键。」

由此，项目从「远程开机」转向「**一键关屏**」，并成为本仓库的正式内容。

### 现状核查结论

| 方式 | 结论 |
|---|---|
| Windows 系统自带快捷键 | **没有**关显示器的全局快捷键；`Win+L` 只是锁屏，屏幕依然亮着 |
| 笔记本 Fn 组合键 | 联想机型不统一（ThinkPad 多为 `Fn+F3`，小新/Legion 常见 `Fn+F2`），本机未装联想显示器切换工具，实测大概率无效 |
| 电源选项自动关屏 | 插电时设为「从不」，存在功能空档 |
| 结论 | **需要自建工具**，且必须补上「只能靠电源键唤醒」以外的说明（Windows 不允许限制唤醒源） |

## 二、向外看：同类优秀项目研究

### 2.1 研究对象与方法

以 `Windows + 关闭显示器 + 小工具 + 开源` 为主线检索，筛出 5 个覆盖面不同的标杆：既包含「极简单功能」路线，也包含「功能全家桶」与「硬件兼容 workaround」路线，保证结论不偏科。

### 2.2 五个案例逐项拆解

#### ① t-mart / monoff —— 极简主义标杆（Rust）

| 维度 | 内容 |
|---|---|
| **核心优势** | 单一职责做到极致：「Run it, and the monitors turn off.」无 GUI、无管理员权限、无后台进程；单 exe 自包含，可从 U 盘直接运行 |
| **特色亮点** | 默认 **100ms 延迟**（专为「手指离开鼠标」这一物理约束设计）；可拖到任务栏当图标用；提供 Scoop / Cargo / binstall 四种安装路径；README 开头直白说明「我为什么做它：显示器电源键够不着」 |
| **UI / 文档审美** | README 用 **Simple / Portable / Convenient / Safe 四个单词小标题**撑起骨架，每项 2–3 句讲完；进阶操作（热键、延迟）收进 `<details>` 折叠；结尾致谢灵感来源。**极简、克制、零截图** |

#### ② LZong-tw / turn-off-screen —— 硬件兼容 workaround（PowerShell）

| 维度 | 内容 |
|---|---|
| **核心优势** | 正面解决真实硬件坑：华硕 ExpertBook 等机型的 `ATKWMIACPIIO` 驱动会**拦截 `SC_MONITORPOWER`**，导致调用的结果是「锁屏」而非「关屏」 |
| **特色亮点** | 亮度设 0 + 全屏黑色遮罩双保险；遮罩用 `WDA_EXCLUDEFROMCAPTURE` 对屏幕捕获隐身（**Chrome 远程桌面看到的是正常桌面，不是黑屏**）；`WS_EX_TRANSPARENT` 点击穿透让远控输入正常；托盘图标作为「遮罩已开启」的可见信号；**再运行一次 = 关闭**（toggle 语义）；监听电源/显示/会话事件自动重贴标志位；RDP 连接时自动退出 |
| **UI / 文档审美** | 含 ASCII 流程框图、**「如何从远程判断遮罩是否开启」状态对照表**、各热键绑定方法表。技术深度型，面向开发者 |

#### ③ 12noonLLC / ScreenSleeper —— 功能矩阵型（C# / .NET）

| 维度 | 内容 |
|---|---|
| **核心优势** | 参数组合最完整：`--idle` 空闲触发 + `--delay` 延迟 + `--standby` 先待机再关闭 + `--lock` 锁屏 + `--sleep` / `--hibernate` |
| **特色亮点** | 用「**Steps**」编号讲清**参数求值顺序**（先 idle → 再 delay → 再 standby → 最后动作），把易混淆的组合讲透；`Example Tasks` 表格把「场景 → 命令」一一对应；文档末尾附微软官方 API 参考链接 |
| **UI / 文档审美** | 朴素但结构严谨，**表格驱动**，无装饰 |

#### ④ Billyas / closeMonitorByHttp —— 远程可编程（Go）

| 维度 | 内容 |
|---|---|
| **核心优势** | 把关屏变成 **HTTP 接口**（默认端口 8233），任何设备、脚本、智能家居都能 `curl` 一下关掉显示器 |
| **特色亮点** | 系统托盘常驻、开机自启、自动生成 exe 图标 |
| **UI / 文档审美** | 中文 README，emoji 小标题（🔌 ✨ 🛠 🚀），篇幅极短，适合中文轻量工具 |

#### ⑤ emoacht / Monitorian —— 成熟商业级参照（C# / WPF，4.5k★）

| 维度 | 内容 |
|---|---|
| **核心优势** | 通过 DDC/CI 协议直接改显示器硬件参数，多显示器可统一或独立控制 |
| **特色亮点** | 显示器重命名、热键绑定、按时间或条件调度、触控板手势 |
| **UI / 文档审美** | 现代 Windows Fluent 设计，**自动跟随系统深浅色主题**；托盘常驻、界面干净 |

### 2.3 提炼：六条值得借鉴的设计思路

| # | 借鉴点 | 来源 | 本项目的落地方式 |
|---|---|---|---|
| 1 | **不做全家桶，只做一件事** | monoff | 工具只负责「关屏」这一个动作，不膨胀成电源管理套件；睡眠/休眠等交给系统 |
| 2 | **延迟不是可选项，而是刚需** | monoff（100ms）、ScreenSleeper（最少 3 秒） | 默认 **1 秒**延迟，并在文档里明确解释「为什么需要」——否则关屏瞬间手还在鼠标上，屏幕立刻被唤醒，表现为「关不掉」 |
| 3 | **同一功能提供多种触达路径** | monoff（任务栏 + 热键）、Twinkle Tray（托盘 + CLI） | 交付**双击即用 exe** + **常驻热键 exe** 双形态，另附 bat / vbs 兜底入口 |
| 4 | **深浅双主题 + 反色适配** | Monitorian（跟随系统主题） | 图标提供 light / dark 两套文件并可一键切换；使用说明页支持主题切换与 `localStorage` 记忆 |
| 5 | **把「现象 ↔ 含义」讲成对照表** | turn-off-screen（托盘图标状态表） | 说明页用表格回答「屏幕黑了一下又亮 / 关不掉 / 亮屏要输密码分别代表什么」 |
| 6 | **README 用单词骨架 + 表格承载信息** | monoff + ScreenSleeper + 中文项目 emoji 习惯 | 本次 README 重构采用：一句话定位 → 徽章 → 目录 → 核心优势表 → 功能表 → 快速开始 → 文档 → 原理图 → FAQ → Roadmap |

### 2.4 本项目的差异化定位

一句话定位：

> **一个不编译、不装运行时、不联网、不常驻的中文关屏小工具 —— 解压双击就黑屏，机器照常运行。**

相对标杆的三点不同：

| 对比对象 | 它们的形态 | 我们的差异 |
|---|---|---|
| monoff / ScreenSleeper | 需 Rust 编译或 .NET 运行时，英文文档 | **绿色 exe 零依赖**，中文文档覆盖到「为什么关不掉」这类实操细节 |
| turn-off-screen | 针对特定厂商驱动坑的单点 workaround | 采用**逐窗口 `SendMessage` + 广播双重兜底**，兼容对广播消息不响应的全屏播放器与旧软件 |
| closeMonitorByHttp | 需要常驻服务并开放端口 | **默认用完即走**，不监听端口、不做后台常驻（仅热键模式按需常驻），减少占用与安全面 |

## 三、向内看：改动逐项记录

> 每条记录包含四项：**动机**（为什么做）· **做法**（怎么做的）· **作用**（产生了什么能力）· **预期效果**（用户侧应看到什么）。

### C1 · 需求可行性与现状核查

| 项 | 内容 |
|---|---|
| **动机** | 用户先问「本机有没有关屏快捷键」，需要给出有依据的答案，而不是「大概没有」 |
| **做法** | 查三处：Windows 快捷方式体系、笔记本 Fn 组合键惯例（含机型识别：本机为联想 82JW）、`powercfg` 导出当前电源方案中「电源按钮 / 合盖 / 关闭显示器超时」的实际取值 |
| **作用** | 确认「系统无现成快捷键」+「插电时显示器从不关闭」两个事实，同时拿到两项关键约束：**不能限制唤醒源**（Windows 无此开关）、**电源键默认行为需调整**以免误触睡眠 |
| **预期效果** | 用户明白「为什么要自己写」，并对工具的行为边界（谁都能唤醒）有正确预期，减少「怎么鼠标一动就亮了」的困惑 |

### C2 · 核心程序 `screen_off.py`

| 项 | 内容 |
|---|---|
| **动机** | 需要「一键关屏、仅关屏、不影响运行」，且要能在别的电脑上跑 |
| **做法** | 用 `ctypes` 直接调用 Win32：向所有可见顶层窗口逐条 `SendMessage(WM_SYSCOMMAND, SC_MONITORPOWER, MONITOR_OFF)`，**再补一次 `SendMessage` 广播 + 一次 `PostMessage` 广播**兜底；参数提供 `--delay` / `--lock` / `--on` / `--hotkey` / `--key` / `--self-test`；只依赖 `argparse / ctypes / sys / time` **标准库** |
| **作用** | 关屏命令的投递成功率显著高于「只广播一次」的常见写法；`--lock` 解决「亮屏后不想被人看到桌面」；`--self-test` 让排障不必真的黑屏 |
| **预期效果** | 双击后约 1 秒黑屏，CPU、内存、磁盘、网络全部照常（下载与后台任务不中断）；换任何 Win8.1+ 机器行为一致 |

### C3 · PyInstaller 打包为独立 exe

| 项 | 内容 |
|---|---|
| **动机** | 目标用户不一定装 Python，且不该为一个小工具配置运行环境 |
| **做法** | `--onefile` 把解释器打进单个 exe；产出两个版本：`关闭屏幕.exe`（`--noconsole`，双击无黑框）与 `关屏热键.exe`（`--console`，常驻热键可见提示） |
| **作用** | 工具脱离本机环境独立运行；两个 exe 对应两种使用姿态 |
| **预期效果** | 拷到任意 Windows 电脑双击即用；单文件约 7.3 MB，无需安装、无需联网 |

### C4 · 桌面快捷方式与全局热键

| 项 | 内容 |
|---|---|
| **动机** | 找图标本身就是一个动作，用户希望「按一下就关」，对应原本期望的「电源键那样的实体感」 |
| **做法** | 用 Windows 快捷方式机制创建桌面 lnk，绑定全局热键 **Ctrl+Alt+Q**，参数固定 `--delay 1`；同时提供 `.py`（pywin32）与 `.vbs`（零依赖）两个生成脚本 |
| **作用** | 热键由系统层面注册，任何界面下按下即生效；换机器时重跑生成脚本即可重建 |
| **预期效果** | 无需找图标，`Ctrl+Alt+Q` 直接关屏；未生效时通常是 Explorer 尚未刷新热键，重登或按 F5 即可 |

### C5 · 图标设计（三轮迭代）

| 项 | 内容 |
|---|---|
| **动机** | 默认 PyInstaller 图标是一只「蛇+盒子」的通用图标，既无辨识度，也不传达「关屏」语义 |
| **做法** | 用 Pillow 以代码绘制（可复现、可改配色）：深色圆角底 + 白色显示器轮廓与底座 + 屏内月牙（寓意「屏幕熄灭」）。第一版深蓝渐变 → 第二版改为纯白底并把线条反色为深蓝 + 浅蓝月牙 → 第三版升级为 **light / dark 双主题**，各自导出独立文件名（`图标-light.ico` / `图标-dark.ico`）以绕开 Windows 图标缓存 |
| **作用** | 三个问题一次性解决：语义可读（一眼看出是屏幕工具）、小尺寸可辨（16→256px 六档尺寸齐全）、主题可切换 |
| **预期效果** | 缩到 32px 仍能认出；放在纯白桌面或深色桌面上都不「隐形」（light 版留了极浅灰描边） |

### C6 · 中文使用说明页 `使用说明.html`

| 项 | 内容 |
|---|---|
| **动机** | 工具面对的是普通使用者，报错时最需要的是「先看哪一条」，而 README 的读者与使用说明的读者不是同一批人 |
| **做法** | 单文件 HTML，7 个章节（快捷键现状 / 文件清单 / 三种用法 / 如何点亮 / 原理 / 排查表 / 附带工具），深色默认 + 一键切浅色 + `localStorage` 记忆，图标以 base64 内嵌保持自包含 |
| **作用** | 把「现象 → 原因 → 处理」做成对照表，比命令行 `--help` 更适合非技术用户 |
| **预期效果** | 遇到「黑了一下又亮」「关不掉」等情况无需求助即可自查解决 |

### C7 · 绿色免安装发布包（修掉本机专属路径）

| 项 | 内容 |
|---|---|
| **动机** | 要把工具发给别人，而早期版本的 `关闭屏幕.bat` 与 `关闭屏幕-静默.vbs` 里**写死了本机 pythonw 的绝对路径**（`C:\Users\15274\.workbuddy\...`），拿到别的电脑必然报「找不到文件」 |
| **做法** | 两个启动器改为**只认同目录下的 `关闭屏幕.exe`**，找不到才回退系统 PATH 的 pythonw 并弹提示；随后用 `发布打包.py` 自动组装 zip，并对产物做 PE 头解析（位数 / 最低系统版本）、exe 自检、ZIP 完整性校验 |
| **作用** | 消除了「只有作者本机能跑」的隐藏缺陷；打包与自检脚本化，改版后可一键重出 |
| **预期效果** | 接收者解压即用，不需要 Python、不需要联网、不需要管理员权限 |

## 四、README 结构优化对照

| 优化前 | 优化后 | 优化理由 |
|---|---|---|
| 无 README | 居中标题 + 一句话中英双语定位 + 徽章行 + 锚点导航 | 首屏建立「是什么 / 给谁用 / 可信度」三件事，锚点导航便于长文跳转 |
| — | **核心优势表**（痛点 → 方案） | 借鉴 monoff 的「单词骨架」思路，改用表格承载「为什么选它」 |
| — | **功能特性表** + 支持的参数表 | 借鉴 ScreenSleeper 的表格驱动写法，把命令与场景一一对应 |
| — | **截图演示**（主视觉 / 完整文档 / 图标） | 文字描述无法传达界面与完整度，图片是最高效的信任凭证 |
| — | **工作原理**（mermaid 流程图 + 链路说明） | 借鉴 turn-off-screen 的画图讲机制，一眼看懂「为什么关屏不影响运行」 |
| — | **和同类工具的差异表** | 把第二章的研究结论落到 README，回答「为什么不直接用 monoff」 |
| — | **FAQ 折叠块**（关不掉 / 黑一下又亮 / 被杀软拦截） | 把踩过的坑前置给用户，降低求助成本 |
| — | **Roadmap + 许可证 + 致谢** | 交代后续方向与授权边界，给共同维护留入口 |

写作原则：**多用表格与清单、少用大段文字；技术术语中英并列；命令加中文注释；不堆砌形容词、不夸大功能**。
